一句话定位

这是 Windows + WSL 工作流里的审批面板，不是通用仪表盘。

它的价值不是“管理一切 agent”，而是把真正值得你决定的动作稳稳接回 Windows 桌面，并且保持终端工作流不中断。

为什么是 helm

专门为 Windows 终端工作流做的产品。

helm 从一开始就是围绕 Windows + WSL 工作流设计的：审批、会话、tray、minibar、回跳和启动链路都统一在桌面侧处理。

人话审批 真正危险的动作会被停下来，让你先看懂再决定。
风险分层 明显低风险的只读检查可以自动放行，高风险动作绝不静默通过。
Windows 原生控制面 审批、历史、活动流、启动面板都留在桌面侧，而不是塞进终端里。

工作方式

hooks 把请求送回桌面，Windows 负责最终决策。

1 接上审批桥 检测 WSL、安装 hooks、验证本地审批服务。
2 从 helm 启动会话 选择 Linux 项目路径和启动方式，helm 负责打开终端会话。
3 在桌面上看请求 命令、文件修改、计划和问题都带着预览和摘要回到面板里。
4 允许、拒绝或回跳 你可以批准、拦下、回答问题，或直接跳回 helm 管理的终端。

FAQ

用户最先会问的几个问题。

会拖慢 agent 吗？ 不会。明显安全的只读命令可以自动放行，只有真正值得你判断的动作才会停下来。
不装 WSL 能用吗？ 不能。helm 的产品边界就是 Windows + WSL 工作流。
能跳回任意终端标签页吗？ 不能。只支持跳回由 helm 自己启动和管理的会话，这样才可靠。
一份购买包含几台设备？ 当前 Beta Access 最多可用于 2 台个人 Windows 设备。
购买之后会得到什么？ 你会拿到当前 Windows beta 版本、beta 期间的持续更新、最多 2 台个人 Windows 设备的使用资格，以及正式版发布后的 1 个月赠送使用期。
这是永久买断吗？ 不是。当前售卖的是面向 Windows + WSL 工作流的 Beta Access，不是覆盖所有未来平台的永久所有权。
更新怎么工作？ helm 可以检查新版本、从 GitHub Releases 下载新版 MSI，并把安装过程交回 Windows。
如果 helm 挂了怎么办？ agent 不会因为桌面层暂时不可用而被卡住。
helm 是面向 Claude Code、Codex、Gemini CLI 的 Windows + WSL 桌面审批层。
